# Patches

Applied to `kubernetes-csi/external-snapshotter` v8.6.0 during build of
the `csi-snapshotter` sidecar. Applied in glob order — `000-vsc-only-mode.patch`
must stay first (the historical build order was fork-branch content first, then
CVE patches).

## 000-vsc-only-mode.patch

Deckhouse fork: VSC-only snapshot content mode (`pkg/vscmode` + sidecar/common
controller wiring). Lets the csi-snapshotter sidecar create and delete physical
snapshots for `VolumeSnapshotContent` objects with a completely EMPTY
`spec.volumeSnapshotRef` (no bound `VolumeSnapshot`) — the VolumeCaptureRequest
flow relies on this. vsc-only is the default mode (`SNAPSHOT_CONTROLLER_VSC_MODE`
unset); legacy per-content behavior is preserved for bound (wired-ref) contents.
Touches `pkg/` only (no `client/`, `vendor/`, `go.mod`). Since v8.6.0 it also
adapts the upstream `pkg/sidecar-controller/csi_handler_test.go` (new in v8.6.0) to
the extra `vscmode.VSCMode` argument of `NewCSIHandler`, passing the legacy mode so
those upstream tests keep their upstream semantics.

This patch is the sole source of the VSC-only changes: they are maintained here as a
patch in this repo, not on any external-snapshotter fork/branch (the `3p`
external-snapshotter repo only mirrors upstream). Keep this file byte-for-byte in sync
with the identically named patch in `images/snapshot-controller/patches/` — same
content, both builds.

## 001-fix-cve.patch

Bumps the modules Trivy flags in the upstream `go.mod` of v8.6.0 to their
minimal fixed releases:

- `github.com/google/cel-go` `v0.28.1 -> v0.29.0` (GHSA-gcjh-h69q-9w9g)
- `golang.org/x/crypto` `v0.52.0 -> v0.57.0` (CVE-2026-56854,
  CVE-2026-56855, CVE-2026-78662)
- `google.golang.org/grpc` `v1.81.1 -> v1.83.2` (GHSA-hrxh-6v49-42gf,
  CVE-2026-84303, CVE-2026-84304, CVE-2026-84445)
- `go.opentelemetry.io/otel/sdk`, `.../exporters/otlp/otlptrace`,
  `.../exporters/otlp/otlptrace/otlptracegrpc` `v1.43.0 -> v1.45.0`
  (CVE-2026-81870)
- `golang.org/x/net` -> `v0.60.0` (CVE-2026-78669) and `golang.org/x/text`
  -> `v0.42.0` (CVE-2026-56851)
- `github.com/klauspost/compress` -> `v1.18.7` (CVE-2026-63209)

Minimal version selection moves the rest of the set along:
`golang.org/x/sys` / `sync` / `term`,
the remaining `go.opentelemetry.io/otel*` modules, `go.opentelemetry.io/proto/otlp`,
`google.golang.org/genproto/googleapis/*` and `github.com/go-logr/logr`.
The remaining `golang.org/x/crypto` advisory GO-2026-5932 has no fixed
release and is covered by `../../known_vulnerabilities.vex`.

Generated by cloning v8.6.0, applying `000-vsc-only-mode.patch`, then
`go get` and `go mod tidy`; touches only `go.mod` / `go.sum` (the build
removes `vendor/` and re-runs `go mod download` / `go mod vendor`). The same
file is applied as `images/snapshot-controller/patches/004-fix-cve.patch`.

## 900-fix-cve-go-deps.patch

Generated by `fix_go_vulns.py` (deckhouse/storage/common) against `v8.6.0` on top of the other patches in this directory; regenerated on every run, do not edit by hand. When the upstream version changes, delete this patch or rerun the script (`fix_go_vulns.py --only <module>`): the old one will not apply to the new tag.
