# Patches

Applied to `kubernetes-csi/external-resizer` v1.14.0 (k8s 1.20 track)
during build of the `csi-resizer` binary.

## 001-fix-cve.patch

Bumps direct/indirect dependencies in `go.mod` / `go.sum` to versions
that fix CVEs reported by Trivy on the v1.14.0 binary:

- `google.golang.org/grpc` `v1.69.2 -> v1.80.0` (fixes CVE-2026-33186)
- `google.golang.org/protobuf` `v1.36.5 -> v1.36.11`

OpenTelemetry indirect deps land at v1.39.0 after `go mod tidy -e`;
that is sufficient for v1.14.0 since Trivy reports no otel CVE here.

Generated by cloning v1.14.0, running `go mod edit -require=...` and
`go mod tidy -e`, then `git format-patch -1`. Only touches `go.mod` /
`go.sum`; the build pipeline does `rm -r vendor && go mod download`
before `make build`. Verified end-to-end inside `golang:1.25-alpine`
with `go build -mod=readonly`.

## 002-fix-cve-golang-x.patch

Bumps `golang.org/x/net` -> `v0.56.0` (CVE-2026-46600) and
`golang.org/x/text` -> `v0.39.0` (CVE-2026-56852) in `go.mod` / `go.sum` to
clear the findings reported by Trivy; this also pulls the transitive
`golang.org/x/crypto` -> `v0.53.0`, `golang.org/x/sys` -> `v0.46.0`,
`golang.org/x/sync` -> `v0.21.0` and `golang.org/x/term` -> `v0.44.0` bumps. Generated by cloning
the pinned upstream version, applying the existing patches, then
`go get`/`go mod tidy` and `git format-patch -1`; touches only
`go.mod` / `go.sum` (the build re-runs `go mod vendor`/`download`).

## 003-fix-cve-grpc-cel-go.patch

Bumps `google.golang.org/grpc` -> `v1.82.1` (GHSA-hrxh-6v49-42gf, xDS RBAC
and HTTP/2 vulnerabilities) to clear the finding reported by Trivy on the
built binary. `github.com/google/cel-go` is not affected in this tree — the
selected version stays below the vulnerable range. Generated by cloning the
pinned upstream version, applying the earlier patches, then `go get` and
`go mod tidy`; touches only `go.mod` / `go.sum` (the build re-runs
`go mod download`/`go mod vendor`).

## 004-fix-cve-grpc-x-crypto.patch

Bumps `google.golang.org/grpc` -> **v1.83.2** (CVE-2026-84304 and
CVE-2026-84303, fixed in 1.83.1, and CVE-2026-84445, fixed in 1.83.2) and
`golang.org/x/crypto` -> **v0.57.0** (CVE-2026-56854, the x/crypto/ssh
source-address authentication bypass, plus CVE-2026-56855 and
CVE-2026-78662) to clear the findings Trivy reported against the built
`csi-resizer` binary. Generated by cloning the pinned upstream version, applying
the earlier patches, then `go get` and `go mod tidy`; touches only
`go.mod` / `go.sum` (the build re-runs `go mod download`/`go mod vendor`). The `go` directive moves to 1.26.0, the language version x/crypto v0.57.0 requires.
The same patch also takes `golang.org/x/net` -> `v0.60.0` (CVE-2026-78669) and `golang.org/x/text` -> `v0.42.0`
(CVE-2026-56851); x/net v0.60.0 also raises `golang.org/x/crypto` to `v0.57.0` and
`golang.org/x/sys` / `sync` / `term` along with it, and `github.com/klauspost/compress` to `v1.18.7`
(CVE-2026-63209).

## 900-fix-cve-go-deps.patch

Generated by `fix_go_vulns.py` (deckhouse/storage/common) against `v1.14.0` on top of the other patches in this directory; regenerated on every run, do not edit by hand. When the upstream version changes, delete this patch or rerun the script (`fix_go_vulns.py --only <module>`): the old one will not apply to the new tag. Raises Go dependencies with known vulnerabilities to the lowest fixed versions:

- `go.mod`: `golang.org/x/net` v0.60.0 → v0.62.0 (CVE-2026-78661, CVE-2026-97045)
- `go.mod`: `golang.org/x/sys` v0.48.0 → v0.49.0
- `go.mod`: `golang.org/x/term` v0.46.0 → v0.47.0
- `go.mod`: `golang.org/x/text` v0.42.0 → v0.43.0
